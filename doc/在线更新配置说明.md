# 在线更新配置说明

本文档说明 AstroToolbox 的在线更新如何配置、发布和验证。

## 一、工作原理

当前在线更新由两部分组成：

1. **更新策略接口**：告诉客户端是否启用更新、当前通道、最新版本、是否强制更新等。
2. **更新产物发布源**：提供 Electron 更新器所需的 Windows 安装包和 `latest.yml`。

客户端启动后会：

- 读取本地更新偏好
- 请求更新策略接口
- 根据策略决定是否检查更新
- 如有新版本，提示用户下载或安装

## 二、必须配置的内容

### 1. 更新策略接口

策略接口由 `UID_MAPPING_API_BASE` 派生，客户端会请求：

```text
GET {UID_MAPPING_API_BASE}/api/config/update-policy
```

例如：

```text
https://your-domain.example.com/api/config/update-policy
```

客户端通过环境变量 `UID_MAPPING_API_BASE` 决定基础地址，因此只需要保证该基础地址可访问，并且它所指向的服务提供更新策略接口即可。

这个接口应返回更新策略 JSON。推荐格式如下：

```json
{
  "success": true,
  "data": {
    "enabled": true,
    "channel": "stable",
    "latestVersion": "0.1.1",
    "publishBaseUrl": "https://your-private-storage.example.com/astro-toolbox/win32/stable/",
    "policyVersion": "2026-04-22-001",
    "releaseNotes": "修复若干问题",
    "forceUpdate": false,
    "rolloutPercent": 100
  }
}
```

字段说明：

- `enabled`：总开关，`false` 时客户端不执行更新检查
- `channel`：更新通道，通常是 `stable` 或 `beta`
- `latestVersion`：当前应升级到的版本号
- `publishBaseUrl`：更新产物发布目录的基础地址
- `policyVersion`：策略版本号，便于审计和排障
- `minimumRequiredVersion`：最低可用版本，低于该版本时视为强更
- `forceUpdate`：是否强制更新
- `rolloutPercent`：灰度比例，范围 0-100
- `releaseNotes`：更新说明
- `downloadPageUrl`：兜底下载页地址
- `signature`：策略签名，可选

### 2. 更新源域名白名单

客户端会校验更新地址必须是 `https`，并且可配置允许访问的域名。

推荐设置：

```bash
UPDATE_ALLOWED_UPDATE_HOSTS=your-private-storage.example.com
```

也可以使用：

```bash
UPDATE_ALLOWED_HOSTS=your-private-storage.example.com
```

如果需要多个域名，可以使用逗号分隔的多个环境变量值，或者在你的启动脚本里逐个注入。

### 3. 应用版本来源

应用版本统一跟随 `package.json` 的 `version` 字段，不再通过环境变量覆盖。

说明：

- 在线更新界面里的“当前版本”直接读取应用自身版本
- 打包、安装和更新比较都以 `package.json` 为准
- 需要变更版本时，请直接修改 `package.json` 中的 `version`

### 4. 更新产物发布目录

将 electron-builder 打包生成的 Windows 更新文件上传到策略接口返回的 `publishBaseUrl` 对应目录下。

通常至少包含：

- `latest.yml`
- Windows 安装包 `.exe`
- 相关辅助文件（如有）

示例目录结构：

```text
https://your-private-storage.example.com/astro-toolbox/win32/stable/
├─ latest.yml
├─ AstroToolbox Setup 0.1.1.exe
└─ AstroToolbox Setup 0.1.1.exe.blockmap
```

## 三、本地运行方式

### 开发环境

启动前注入环境变量，例如：

```bash
UPDATE_ALLOWED_UPDATE_HOSTS=your-private-storage.example.com
UID_MAPPING_API_BASE=https://your-domain.example.com
npm run dev
```

注意：开发模式下建议只做联调，不要直接依赖真实线上更新源做最终验证。

### 打包后验证

推荐使用打包后的安装版验证在线更新，因为 Electron 更新器的行为与安装包、签名和发布目录强相关。

验证流程：

1. 打包并安装旧版本
2. 上传新版本安装包和 `latest.yml`
3. 确保策略接口返回更高的 `latestVersion`
4. 打开已安装版本，点击“检查更新”
5. 验证是否能正常提示、下载和安装

### 5. 安装器目录选择

当前 Windows 安装包使用 NSIS 向导模式，安装时会显示目录选择页面。

如果你不想让安装器直接一键安装，请确认 `package.json` 中的 NSIS 配置保持：

- `oneClick: false`
- `allowToChangeInstallationDirectory: true`

## 四、用户配置项

应用会把以下偏好保存在本地配置中：

- `autoUpdateEnabled`：是否允许自动检查更新
- `updateChannel`：更新通道
- `skippedUpdateVersion`：用户跳过的版本号

这些配置会影响客户端是否自动检查、检查哪个通道，以及是否忽略某个版本。

## 五、强制更新规则

当策略接口返回以下任一条件时，客户端会把更新视为强制更新：

- `forceUpdate = true`
- 当前版本低于 `minimumRequiredVersion`

强制更新时，客户端会优先引导安装，不建议继续使用旧版本。

## 六、推荐部署流程

1. CI 构建 Windows 安装包
2. 将安装包、`latest.yml` 和相关文件上传到私有对象存储
3. 更新策略接口中的 `latestVersion` 和 `publishBaseUrl`
4. 如有需要，调整 `forceUpdate`、`minimumRequiredVersion`、`rolloutPercent`
5. 客户端通过策略接口获取更新行为

## 七、最小可用配置清单

要让在线更新生效，至少需要：

- 一个可访问的 `UID_MAPPING_API_BASE`
- 该基础地址下可访问的 `GET /api/config/update-policy`
- 一个可访问的 Windows 更新发布目录
- 正确配置的 `UPDATE_ALLOWED_UPDATE_HOSTS` 或 `UPDATE_ALLOWED_HOSTS`
- 打包后的 Windows 安装版进行验证

## 八、常见问题

### 1. 为什么开发模式下看不到更新？

更新机制主要面向已打包安装版。请优先在安装后的应用里验证。

### 2. 为什么检查更新没有结果？

常见原因包括：

- 策略接口不可访问
- 更新源地址没有加入白名单
- `publishBaseUrl` 配置错误
- 发布目录里缺少 `latest.yml`

### 3. 为什么安装包下载后无法安装？

常见原因包括：

- 安装包未正确上传
- 安装包和 `latest.yml` 不匹配
- Windows 安装包签名或安全策略问题

## 九、建议的后续检查

如果你要正式上线，建议再确认：

- 更新源使用 HTTPS
- Windows 安装包已签名
- 策略接口有审计日志
- 发布目录可回滚到上一版本
- 灰度策略和强更策略都有兜底
- 安装器使用 `oneClick: false` 才会显示目录选择
